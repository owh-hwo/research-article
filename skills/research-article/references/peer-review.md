# ขั้น 9.5 — จำลองการพิจารณาบทความโดยแยกผู้ตรวจตามบทบาท

ใช้ **subagent ของ Claude Code ผ่าน Agent tool เท่านั้น** ผู้ทรงคุณวุฒิแต่ละท่านเป็นคนละ subagent และตรวจอิสระ ไม่ให้ agent เดียวสวมหลายบทบาท ไม่ใช้ CLI หรือบริการ AI ภายนอกเป็นผู้ตรวจ Claude หลักรับบทผู้เขียนและผู้ประสานงาน ผลทั้งหมดเป็นการจำลอง ไม่ใช่การพิจารณาจริงของวารสาร

## เตรียมบทบาทและไฟล์

อ่านบทความก่อนเลือกสาขา ไม่กำหนดสาขาตายตัวตามตัวอย่างเดิม ใช้กองบรรณาธิการหนึ่งบทบาทจาก `<plugin-root>/agents/article-editor.md` และผู้ทรงฯ สองถึงสามท่านจาก `<plugin-root>/agents/article-reviewer.md` โดยกำหนดมุมมองต่างกัน:

| บทบาท | หลักเลือกสาขาและหน้าที่ |
|---|---|
| กองบรรณาธิการ | เกณฑ์วารสาร ขอบเขต รูปแบบ ความยาว PDF และการรวมผล |
| ผู้ทรงฯ สาขาหลัก | แนวคิด ทฤษฎี ความใหม่ และข้อสรุปหลักของเรื่อง |
| ผู้ทรงฯ สาขาบริบท | การประยุกต์ในบริบทหรืออุตสาหกรรมที่ศึกษา นิยามและข้อจำกัดการใช้ผล |
| ผู้ทรงฯ ท่านที่สามเมื่อจำเป็น | โหมด MCU ใช้ด้านหลักธรรม; บทความวิจัยใช้ด้านระเบียบวิธี/สถิติ |

ถ้าบทความวิจัยอยู่ในโหมด MCU ให้จัดสามท่านครอบคลุมสาขาหลักและบริบทในมุมมองเดียวกัน อีกสองท่านตรวจหลักธรรมและระเบียบวิธี ระบุเหตุผลการจัดบทบาทและส่วนที่ยังไม่ครอบคลุม ไม่เพิ่มท่านที่สี่โดยอัตโนมัติ ไม่จำเป็นต้องมี agent ตรวจอ้างอิงแยก: ผู้ทรงฯ ทุกท่านตรวจแหล่งที่เกี่ยวกับข้อสรุปในสาขาตน กองบรรณาธิการตรวจรูปแบบและความครบถ้วน

Claude หลักรวบรวมรายการไฟล์พร้อมรุ่น/วันที่สร้างและเส้นทางจริงก่อนเรียก:

- `<workdir>/draft.md`, PDF ฉบับส่งและสำเนาสำหรับตรวจหน้า (ระบุว่าฉบับใดใช้ฟอนต์แทน), ภาพใน `figures/` และขนาดวางจริง หากยังไม่มี PDF ให้ทำขั้น 10 ก่อนเริ่มรอบ หรือระบุงานตรวจรูปแบบที่ยังค้าง
- `refs.json`, `refs-dropped.json`, `refs-log.md`, ไฟล์ผลค้นจริงทั้งหมด (แยกฐาน คำค้น และการค้นเพิ่ม), `fulltext/` พร้อมสถานะว่าแหล่งใดมีเพียงบทคัดย่อ
- `<journal-docs>`: ขอบเขตวารสาร คำแนะนำผู้เขียน แม่แบบ และบทความที่ตีพิมพ์จริง; ส่งข้อความที่สกัดจากเอกสารควบคู่ต้นฉบับ หากเครื่องมืออ่านรูปแบบนั้นไม่ได้
- `brief.md`, `checklist.md`, `<skill-dir>/references/review-lessons.md`, คู่มือนี้ และ `<thai-humanizer-dir>/references/thai-humanizer.md` กับ `thai-prose-patterns.md` สำหรับสำนวน อ้างไฟล์คู่หูเท่านั้น ไม่คัดลอกเข้าปลั๊กอิน
- รอบหลังเพิ่มรายงานรวม รายงานบทบาทเดิม และ `response-to-reviewers.md` จากรอบก่อน รวมทั้งรายการเปลี่ยนแปลงหรือสำเนาร่างก่อนแก้ หากไม่มีร่างเก่า ให้บอกขอบเขตที่เทียบก่อน–หลังไม่ได้

ส่งรายชื่อไฟล์จริง ไม่ส่งเพียงชื่อโฟลเดอร์ที่คาดว่ามีไฟล์อยู่ แหล่งที่ขาดให้ Claude หลักจัดหาหรือส่งข้อความต้นทางพร้อมเลขหน้า ผู้ตรวจไม่มีสิทธิใช้เครือข่ายหรือเรียกสคริปต์จากชุดบทความเพื่อค้นเอง

## โครงผลตรวจและการเรียกขนาน

Claude หลักสร้างโฟลเดอร์ก่อนและกำหนดชื่อบทบาทคงที่ตลอดเรื่อง:

```text
<workdir>/reviews/roundN/editor.md
<workdir>/reviews/roundN/reviewer-main.md
<workdir>/reviews/roundN/reviewer-context.md
<workdir>/reviews/roundN/reviewer-specialist.md  เมื่อใช้ท่านที่สาม
<workdir>/review-roundN.md                    รายงานรวมโดยกองบรรณาธิการ
<workdir>/response-to-reviewers.md            ตารางตอบแยกรอบโดย Claude หลัก
```

ใช้เลขรอบจริงแทน `N` ไม่เขียนทับรายงานรอบก่อน ห้ามแก้ไฟล์ต้นทางระหว่างผู้ตรวจทำงาน เก็บภาพเรนเดอร์ที่ Claude หลักเตรียมไว้ใน `<workdir>/reviews/roundN/pages/` แยกชื่อ PDF และเลขหน้า ผู้ตรวจอ่านภาพเหล่านี้ด้วย Read ได้ และต้องทราบว่าภาพมาจาก PDF รุ่นใด

1. เรียก `research-article:article-editor` โหมดด่านแรกและ `research-article:article-reviewer` แยกตามสาขา **ในหนึ่งข้อความที่มีหลาย Agent tool call** งานแต่ละตัวได้รับบทบาท รายการไฟล์ และไฟล์ผลเฉพาะของตัวเอง ผู้ทรงฯ ไม่อ่านผลของคนอื่นในรอบปัจจุบัน หากทรัพยากรจำกัดให้แบ่งชุดคิวโดยยังแยกบริบทแต่ละคน
2. ตัวอย่างอาร์กิวเมนต์ต่อหนึ่งการเรียก (แทน placeholder และตรวจชื่อเครื่องมือ/พารามิเตอร์ที่มีใน session จริง):

```json
{
  "subagent_type": "research-article:article-reviewer",
  "description": "ตรวจสาระตามสาขาหลัก",
  "prompt": "คุณเป็นผู้ทรงคุณวุฒิสาขา <สาขา> บทความ <รหัสบทความ> รอบ <N> อ่านคู่มือ <skill-dir>/references/peer-review.md ใช้คำสั่งรอบที่กำหนดพร้อมรายการไฟล์จริงต่อท้าย เขียนเฉพาะ <workdir>/reviews/roundN/reviewer-main.md",
  "run_in_background": true
}
```

3. เปลี่ยน `subagent_type` เป็น `research-article:article-editor` สำหรับกองบรรณาธิการ ระบุโหมดด่านแรกและผล `<workdir>/reviews/roundN/editor.md` ส่วนผู้ทรงฯ คนอื่นใช้ชนิดเดิมแต่คนละสาขาและไฟล์ผล ห้ามใช้ prompt ย่อด้านบนแทนรายการข้อมูลในแม่แบบด้านล่าง
4. เมื่องานนาน ใช้ `run_in_background` ถ้ารุ่นที่ใช้รองรับ เก็บรหัสงานคู่กับบทความ/รอบ/บทบาท ติดตามด้วยเครื่องมืองานที่ session ให้มา รอผลเสร็จจริงและอ่านรายงานครบก่อนรวม หากงานล้มเหลวหรือรายงานไม่ครบให้รายงานสถานะและเรียกซ่อมเฉพาะงานนั้น ไม่ถือว่าความเงียบคือยอมรับ
5. หลังผลครบ เรียก editor โหมดรวมผล โดยส่งผลด่านแรกและไฟล์ผู้ทรงฯ ของบทความนี้เท่านั้น พร้อมรายการบทบาทที่คาดว่าจะครบ ให้เขียน `<workdir>/review-roundN.md` การเรียกนี้เป็นขั้นต่อเนื่องของบทบาทกองบรรณาธิการเดิม จะเรียกต่อจากบริบทเดิมหรือเริ่มบริบทใหม่พร้อมไฟล์ด่านแรกก็ได้

หลายบทความให้จัดตารางคิว `บทความ | workdir | รอบ | บทบาท/สาขา | รหัสงาน | ไฟล์ผล | สถานะ` แล้วส่ง subagent แยก **บทความ × บทบาท** ในข้อความเดียวกันได้ แต่ละบทความใช้ workdir คนละแห่ง และมี editor รวมเฉพาะชุดของตน ไม่ใช้ไฟล์ผลร่วมกัน แม้ชื่อบทบาทเหมือนกัน งานรวมผลของบทความที่ครบแล้วเริ่มได้โดยไม่ต้องรอบทความอื่น

ปลั๊กอินค้นพบ `agents/` ที่รากโดยอัตโนมัติ จึงไม่ต้องเพิ่ม path ใน manifest หากติดตั้งเฉพาะโฟลเดอร์สกิลจะไม่ได้ agent เหล่านี้ ให้แจ้งว่าต้องโหลดปลั๊กอินหรือให้ Claude Code ลงทะเบียน agent จากไฟล์ที่ระบุ ห้ามเปลี่ยนไปใช้เครื่องมือผู้ตรวจภายนอกหรือให้ Claude หลักสวมบทผู้ตรวจแทนโดยไม่บอก

## แม่แบบคำสั่งรอบที่ 1

ใช้ข้อความนี้แยกส่งให้แต่ละบทบาท เติมรายการไฟล์จริงและข้อมูลที่ขาดก่อนเรียก:

```text
คุณคือ <กองบรรณาธิการโหมดด่านแรก / ผู้ทรงคุณวุฒิหนึ่งท่านสาขา ...>
บทความ <รหัสบทความ> ประเภท <วิจัย/วิชาการ> โหมด <MCU/ทั่วไป> รอบที่ 1
มุมมองและขอบเขตเฉพาะของคุณ: <...>
คู่มือ: <skill-dir>/references/peer-review.md และ review-lessons.md
เกณฑ์สำนวน: <thai-humanizer-dir>/references/thai-humanizer.md และ thai-prose-patterns.md
ไฟล์ผลของคุณเท่านั้น: <workdir>/reviews/round1/<role>.md

ชุดไฟล์และรุ่น: <รายการ draft.md, PDF ทุกฉบับ, ภาพพร้อมขนาดวางจริง,
refs.json, refs-dropped.json, refs-log.md, ไฟล์ผลค้นทั้งหมด, fulltext/,
brief.md, checklist.md, <journal-docs> พร้อมคำแนะนำ แม่แบบ และบทความตีพิมพ์จริง>
ไฟล์ที่ขาด/เก่า: <รายการ หรือ ไม่มี> ภาพหน้าที่เตรียมไว้: <รายการและ PDF ต้นทาง>
ข้อมูลสำคัญ: <เพดานหน้าและวิธีนับ, ฟอนต์จริง/ฟอนต์แทน,
ข้อจำกัดสคริปต์ที่ยืนยันแล้วพร้อมหลักฐาน, ส่วนที่ผู้เขียนยังต้องทำเอง>

ตรวจอิสระจากเนื้อหาจริงและแหล่งต้นทาง ไม่เชื่อ checklist หรือยอดสรุป
ผู้ทรงฯ ตรวจข้ออ้างหลัก ตัวเลข ข้อความยกตรง และตรรกะตามสาขา
นับเอกสารจากผลค้นเองและจับคู่การอ้างอิงกับท้ายเรื่อง
กองบรรณาธิการเทียบเกณฑ์วารสารและดูภาพ PDF ทีละหน้าครบทุกฉบับปัจจุบัน
ทุกข้อวิจารณ์ต้องมีบรรทัด/หน้าและหลักฐาน ห้ามแต่งข้อมูลที่ขาด
ให้คำตัดสินพร้อมเหตุผลและตาราง "สิ่งที่ต้องแก้":
ลำดับ | ตำแหน่ง | ปัญหา | หลักฐาน | สิ่งที่ต้องแก้ | ระดับ: บังคับ/ควรแก้/ข้อเสนอ
ตาราง "ข้อเสนอด้านสำนวน": ตำแหน่ง | ข้อความเดิม | ข้อความเสนอ
แยกงานที่ผู้เขียนต้องทำเอง งานรอไฟล์ใหม่ และข้อจำกัดออกจากคำตัดสิน
ถ้าหลักฐานที่ขาดกระทบข้อสรุปหลัก ให้คงเป็นข้อค้างด้านสาระ
อ่านอย่างเดียว ยกเว้นเขียนรายงานของตนตามสิทธิใน agent ห้ามแก้ต้นฉบับ
ระบุชัดว่าเป็นการจำลอง ไม่รับประกันผลวารสารจริง
```

## แม่แบบคำสั่งรอบที่ N

ใช้บทบาทและสาขาเดิมเพื่อให้ติดตามประเด็นได้ แม้เปิด subagent ใหม่ก็ต้องให้รายงานเดิมและข้อยุติครบ ไม่อาศัยความจำของการสนทนา:

```text
คุณคือ <บทบาท/สาขาเดิม> บทความ <รหัสบทความ> รอบที่ <N>
ไฟล์ผลของคุณเท่านั้น: <workdir>/reviews/roundN/<role>.md
คู่มือ เกณฑ์วารสาร เกณฑ์สำนวน และชุดไฟล์: <รายการเหมือนรอบแรกพร้อมรุ่นล่าสุด>
ผลก่อนหน้า: <workdir>/review-round<รอบก่อน>.md และรายงานบทบาทเดิม
ตารางตอบ: <workdir>/response-to-reviewers.md หัวข้อรอบ <รอบก่อน>
ร่างก่อนแก้/รายการเปลี่ยนแปลง: <ไฟล์ หรือระบุว่าไม่มี>

ข้อค้างที่ต้องตรวจทีละข้อ: <รหัสบทบาท:ข้อ + ข้อเสนอด้านสำนวนทุกจุด>
ข้อยุติแล้ว: <รหัสข้อ เหตุผล และหลักฐานที่ยุติ>
ไฟล์ที่ยังไม่ได้สร้างใหม่: <รายการ/รุ่นเก่า หรือ ไม่มี>
ข้อมูลสำคัญของรอบ: <ความยาวชนเพดาน, จุดที่เพิ่ม/ตัด,
ข้อจำกัดสคริปต์ที่ยุติแล้วพร้อมเหตุผล, ฟอนต์/ขนาดภาพ/วิธีสร้างไฟล์>
งานที่ผู้เขียนต้องทำเอง: <รายการและเหตุผล>

1. ตรวจข้อค้างและสำนวนเดิมทุกข้อจากเนื้อหาจริง เทียบแหล่งต้นทาง
ให้สถานะ แก้แล้ว / แก้บางส่วน / ยังไม่แก้ พร้อมบรรทัด/หน้า
อย่าเชื่อตารางตอบ ถ้าตรวจผลจากไฟล์ใหม่ไม่ได้ ให้ระบุ "ตรวจไม่ได้ในรอบนี้"
และเหตุผล เช่น รอ PDF ใหม่ ไม่ใช้ไฟล์เก่าตัดสินการแก้ล่าสุด
2. ข้อที่ยุติแล้วห้ามเปิดซ้ำ เว้นแต่การแก้ทำให้กลับมาผิดโดยมีหลักฐานใหม่
3. ตรวจข้อความเพิ่ม/ตัดทุกจุดว่าคงข้อเท็จจริง ระดับความมั่นใจ เงื่อนไข
สิ่งที่แหล่งวัด และการอ้างอิง โดยเฉพาะหลังย่อเพื่อให้พอดีหน้า
เทียบ draft.md กับ refs.json ภาพ ตาราง และบทคัดย่อทั้งสองภาษา
4. กองบรรณาธิการตรวจ PDF ใหม่ทีละหน้า ถ้าไม่มีไฟล์ใหม่ให้คงงานรอตรวจ
5. ให้คำตัดสินและตารางสิ่งที่ยังต้องแก้/ข้อเสนอสำนวนตามแม่แบบรอบแรก
แยกงานผู้เขียนเองและงานรอ PDF ออกจากคำตัดสิน ไม่ย้ายข้อผิดสาระไปหมวดงานผู้เขียน
ทำงานตามสิทธิใน agent และระบุว่าเป็นการจำลอง
```

คำสั่ง editor โหมดรวมผลให้เติม `รายชื่อบทบาทที่ต้องครบ`, `ไฟล์ผลแต่ละบทบาท`, `ไฟล์ด่านแรก`, `บทความ/รอบ/รุ่นไฟล์` และ `ไฟล์รวมปลายทาง` ย้ำให้คงคำตัดสินรายบุคคล รวมข้อซ้ำพร้อมรหัสต้นทาง และแสดงความเห็นต่างที่ยังหาข้อยุติไม่ได้ ไม่ส่งรวมก่อนรายงานครบ

## หลังได้รับรายงาน

1. Claude หลัก **เทียบข้อเสนอทุกข้อกับแหล่งก่อนรับ** รวมทั้งข้อเสนอสำนวน ถ้าเป็นข้อเสนอเพิ่มหัวข้อให้เทียบแม่แบบและบทความตีพิมพ์จริง หากไม่จำเป็นให้ตอบในส่วนเดิม ถ้าขัดหลักฐานให้ไม่รับพร้อมเหตุผล
2. วางแผนเพิ่มและตัดพร้อมกันเมื่อความยาวใกล้เพดาน แก้ร่าง `refs.json` และไฟล์ประกอบที่เกี่ยวข้องให้ตรงกัน หลังย่อกลับไปตรวจเงื่อนไขกับต้นทางอีกครั้ง
3. ทำ `response-to-reviewers.md` แยกหัวข้อแต่ละรอบ เก็บรหัสผู้ตรวจและข้อเดิมไว้ แม้รายงานรวมจะรวมข้อซ้ำ:

| รหัสผู้ตรวจ:ข้อ | ข้อคิดเห็น | การแก้/เหตุผล | ตำแหน่ง/หลักฐาน | สถานะ |
|---|---|---|---|---|
| <role>:<ข้อ> | <ข้อคิดเห็น> | <สิ่งที่ทำหรือเหตุผลไม่รับ> | <ไฟล์ บรรทัด/หน้า รุ่น> | <สถานะ> |

ใช้สถานะ **แก้แล้ว** (แก้ต้นฉบับแล้ว ยังไม่รับรอง PDF), **แก้แล้ว-ตรวจใน PDF แล้ว** (ดูไฟล์ใหม่จริง ระบุไฟล์ หน้า และวันที่/วิธีสร้าง), **แก้บางส่วน** (รวมงานยังค้าง พร้อมสิ่งที่เหลือ), **ไม่แก้-เหตุผล** (ระบุเหตุผลและหลักฐาน) ตอบทุกข้อ ข้อเสนอสำนวนตอบเป็นกลุ่มได้เมื่อแจกแจงจุดที่ไม่รับหรือปรับต่างไว้ครบ

4. ถ้ารอบก่อนระบุว่าแก้แล้วแต่ผู้ตรวจพบว่ายังไม่สำเร็จ ให้แก้ **แถวเดิมเป็น “แก้บางส่วน”** พร้อมเหตุผลและลิงก์รอบที่แก้ต่อ รักษาข้อความการดำเนินการเดิมและวันที่แก้สถานะ ไม่ลบประวัติหรือเขียนทับผลผู้ตรวจ
5. สร้าง DOCX/PDF/ภาพที่เปลี่ยนใหม่ก่อนส่งรอบถัดไป รันตัวตรวจอ้างอิง สำนวน และ `check_linebreaks.py` ตามขั้น 9–10 ดู PDF จริงแล้วปรับ `checklist.md` ตามผลจริง ถ้ายังสร้างไม่ได้ ให้ระบุไฟล์นั้นว่าตรวจไม่ได้และส่งตรวจได้เฉพาะสาระที่ยืนยันจากร่าง ห้ามรับรองว่าไฟล์ส่งพร้อม
6. ทำรอบต่อไปจน **ผู้ทรงฯ ทุกท่านยอมรับด้านสาระ และกองบรรณาธิการเหลือเฉพาะงานที่ผู้เขียนต้องทำเอง** หรือผู้ใช้สั่งหยุด PDF ที่ยังไม่สร้างใหม่ คำตัดกลางคำ หรือรายงานผู้ตรวจที่ยังขาด ไม่เข้าเกณฑ์หยุดว่าผ่าน หากติดขัดให้รายงานสถานะจริง ไม่วนเรียกซ้ำโดยไม่มีไฟล์หรือหลักฐานใหม่

## บทเรียนเชิงปฏิบัติและข้อจำกัด

- ผู้ตรวจต้องนับเอกสารเองจากผลค้นทั้งหมด ยอดที่แสดงบนหน้าจออาจไม่เท่าระเบียนในไฟล์ และเอกสารตัวอย่างวารสารไม่ใช่ผลค้นงานที่ใช้เป็นหลักฐาน
- ตัวตรวจอ้างอิงอาจจับคู่ผิดเมื่อท้ายเรื่องลงผู้แต่งครบแต่เนื้อหาใช้ “และคณะ” ให้จับคู่ด้วยตาจากชื่อ ปี และชื่อเรื่อง บันทึกข้อจำกัดที่ยืนยันแล้ว ไม่แก้บรรณานุกรมที่ถูกต้องเพื่อให้สคริปต์เงียบ
- ข้อเสนอเพิ่มเนื้อหาอาจดันความยาวเกินเพดาน ต้องระบุส่วนที่ตัดได้โดยไม่เสียหลักฐานและตรวจอ้างอิงอีกครั้ง ไม่ลดขนาดตัวอักษรขัดเกณฑ์เพื่อบีบหน้า
- คำไทยถูกตัดต้องตรวจจาก PDF ใหม่ทุกครั้ง การเปลี่ยนถ้อยคำไม่ได้รับประกันว่าจะหาย ส่วนท้ายคำอาจกลายเป็นคำอื่นที่มีความหมาย เช่น “เสนอกรอบ” ถูกตัดเป็น “เส / นอกรอบ” การตัดคำจากข้อความรอบรอยต่อใหม่อาจอ่านเป็น “นอก” และพลาด จึงใช้ขอบเขตคำจากร่างเป็นตัวอ้างอิง
- เรียงถ้อยคำเฉพาะจุดใหม่โดยคงความหมายมักปลอดภัยกว่าการใส่อักขระกันตัดทั้งไฟล์ ซึ่งเปลี่ยนการจัดบรรทัดและจำนวนหน้า จากนั้นตรวจไฟล์ที่สร้างใหม่ทุกฉบับ
- `check_linebreaks.py` ต้องมี `pythainlp` และ `pypdfium2` ใช้ข้อความ PDF ที่สกัดได้และขอบคำจากร่าง ผลไม่พบไม่รับรองทั้งเอกสาร: PDF สแกน การเรียงข้อความหลายคอลัมน์ อักขระสกัดผิด คำเฉพาะที่ตัวตัดคำไม่รู้จัก และรอยต่อข้ามหน้าที่มีหัว/ท้ายหน้าอาจตรวจไม่ได้ ต้องดูภาพหน้าและเทียบร่างเสมอ
- สคริปต์ใช้ `newmm` เป็นหลัก และเทียบ `longest` เฉพาะจุดที่แบ่งพยางค์สระนำสั้น เช่น “เส” เพื่อกู้ขอบคำที่กำกวมโดยไม่เหมารวมคำประสมทั้งหมดว่าห้ามขึ้นบรรทัด วิธีนี้เป็นการประมาณ ไม่ครอบคลุมความกำกวมภาษาไทยทุกชนิด รายงานเป็นจุดให้คนยืนยัน ไม่ใช่คำตัดสินอัตโนมัติ

รูปแบบ agent และการโหลดตรวจสอบได้จาก [เอกสารปลั๊กอิน Claude Code](https://code.claude.com/docs/en/plugins-reference) และ [เอกสาร subagent](https://code.claude.com/docs/en/sub-agents) ใช้พารามิเตอร์ตามเครื่องมือที่ session ปัจจุบันรองรับ
