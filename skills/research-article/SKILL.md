# Research Article Writer (บทความวิจัย / บทความวิชาการ)

สกิลนี้พาผู้เขียนจาก "หัวข้อที่สนใจ" ไปจนถึง "ไฟล์ .docx พร้อมส่งวารสาร" โดยยึดหลัก 3 ข้อที่ห้ามละเมิด

1. **อ้างอิงต้องมีจริงและตรวจได้** ทุกรายการต้องค้นและเปิดดูข้อมูลจริง (TCI, ThaiJO, เว็บวารสาร, DOI, หนังสือที่ผู้ใช้มี) ห้ามแต่งชื่อผู้แต่ง ชื่อเรื่อง ปี เลขหน้า หรือ URL ถ้าตรวจไม่ได้ให้ตัดทิ้งและหาใหม่
2. **อ้างอิงอย่างน้อย 10 แหล่ง** ทั้งสองโหมด ทุกรายการที่อ้างในเนื้อหาต้องอยู่ท้ายเรื่อง และกลับกัน
3. **ห้ามสร้างข้อมูลวิจัยขึ้นเอง** ผลการวิจัย ตัวเลข กลุ่มตัวอย่าง คำสัมภาษณ์ ต้องมาจากผู้เขียนเท่านั้น ถ้ายังไม่มี ให้เว้น `[รอข้อมูล: ...]` แล้วแจ้งผู้ใช้

## ทรัพยากรของสกิล

| ไฟล์ | ใช้เมื่อ |
|---|---|
| `references/topic-ideation.md` | ขั้น 0.5 ช่วยเลือกหัวข้อจากเนื้อหาหลักที่ผู้ใช้บอก |
| `references/interview.md` | ขั้นที่ 1 ชุดคำถามสัมภาษณ์ |

| `references/general-journals.md` | โหมดทั่วไป: วิธีเก็บเกณฑ์ของวารสารเป้าหมายและปรับโครงสร้าง |

| `references/search-sources.md` | แหล่งค้นวิชาการสาธารณะอื่น ชุดแนะนำตามสาขา หลักคัดกรองคุณภาพ |

### สกิลคู่หู (ถ้าติดตั้งไว้)
- `grill-me` — สัมภาษณ์ทีละคำถามพร้อมคำตอบแนะนำ (ขั้น 1) ถ้าไม่มี ให้ทำตามกติกาใน `interview.md` เอง
- `diagram-design` — สร้างแผนภาพ HTML/SVG/PNG (ขั้น 7) ถ้าไม่มี ให้สร้าง SVG/HTML เองแล้วแปลงเป็น PNG
- `humanizer` — ปรับภาษาไม่ให้เป็น AI (ขั้น 8) ใช้คู่กับ `thai-humanizer.md` เสมอ ถ้าไม่มี ใช้ `thai-humanizer.md` อย่างเดียว
- `docx` — แก้ไข .docx ขั้นสูงหรือเทเนื้อหาลง template ของวารสาร

## พื้นที่ทำงานของแต่ละบทความ

ถามผู้ใช้ว่าจะเก็บงานที่ใด ถ้าไม่ระบุ ใช้ `./articles/<ชื่อย่อบทความ>/` ในไดเรกทอรีปัจจุบัน

```
fulltext/         ฉบับเต็ม PDF/ข้อความของแหล่งที่อ่าน (ขั้น 3)
refs-dropped.json รายการที่ตัดออกพร้อมเหตุผล
response-to-reviewers.md  ตารางตอบผู้ตรวจแต่ละรอบ (ขั้น 9.5)
topic-options.md  ตัวเลือกหัวข้อ ผลสแกน คะแนน (ขั้น 0.5)
brief.md          หัวข้อที่เลือก ผลการสัมภาษณ์ และเกณฑ์วารสาร (ขั้น 0.5-2)
refs.json         รายการอ้างอิงที่ตรวจแล้ว (ขั้น 3-4)
refs-log.md       บันทึกการค้น: คำค้น ผลที่ได้ เหตุผลที่เลือก/ตัด
outline.md        โครงเรื่อง (ขั้น 5)
draft.md          ต้นฉบับ (ขั้น 6-8)
figures/          แผนภาพ .html + .png (ขั้น 7)
<ชื่อ>.docx       ไฟล์ส่งวารสาร (ขั้น 10)
checklist.md      ผลตรวจก่อนส่ง (ขั้น 9)
```

ถ้าผู้ใช้มีเอกสารของตนเอง (คำแนะนำผู้เขียนของวารสาร, template, บทความตัวอย่าง, คู่มือหลักธรรมของหลักสูตร, งานวิจัยที่อยากอ้าง) ให้ขอ path/ลิงก์แล้วอ่านก่อนเริ่ม เก็บข้อความที่สกัดได้ไว้ในโฟลเดอร์งานของบทความนั้น

## ขั้นตอนการทำงาน

### ขั้น 0 — เลือกโหมด

ถามผู้ใช้ (AskUserQuestion) ถ้ายังไม่ได้บอก:
- **โหมด MCU** — วารสารสายพุทธบูรณาการ (เช่น วารสารในเครือ มหาวิทยาลัยมหาจุฬาลงกรณราชวิทยาลัย) ต้องบูรณาการหลักพุทธธรรมและอ้างพระไตรปิฎก
- **โหมดทั่วไป** — วารสารอื่น ไม่บังคับหลักธรรม (ใส่ได้ถ้าผู้เขียนต้องการ) ใช้เกณฑ์ของวารสารเป้าหมาย

และถามประเภท: บทความวิจัย หรือ บทความวิชาการ

### ขั้น 0.5 — ช่วยเลือกหัวข้อ (เมื่อยังไม่มีชื่อเรื่องชัด)

ถ้าผู้ใช้บอกแค่เนื้อหาหลัก/เรื่องที่สนใจ หรือขอให้ช่วยหาหัวข้อ ให้ทำตาม `references/topic-ideation.md`:
1. รับวัตถุดิบ (เล่าอิสระหรือไฟล์) ถามเสริมเฉพาะที่ขาด
2. แตกองค์ประกอบ: ตัวแปร บริบท ทฤษฎี หลักธรรม มุมร่วมสมัย ผลลัพธ์
3. สร้างหัวข้อ 5-8 ตัวเลือกตามแบบแผนชื่อเรื่อง (ปลอดภัย / มุมใหม่ / ทำได้เร็ว)
4. สแกนทุกตัวเลือกด้วย `topic_scan.py` และอ่านตัวอย่างงานล่าสุดเพื่อตัดหัวข้อที่ซ้ำกับงานที่มีอยู่
5. ให้คะแนน (ความใหม่ ความพอของอ้างอิง ความเป็นไปได้ ขอบเขตวารสาร ความทันสมัย) เสนอ 3 อันดับพร้อมชื่อไทย/อังกฤษ ปัญหา วัตถุประสงค์ร่าง ทฤษฎี/หลักธรรม ข้อมูลที่ต้องมี ความเสี่ยง
6. ให้ผู้ใช้เลือก แล้วบันทึกลง `brief.md` และ `topic-options.md` ก่อนเข้าขั้น 1 (ข้ามคำถามที่ได้คำตอบแล้ว)

ถ้าผู้ใช้มีชื่อเรื่องอยู่แล้ว ยังควรรัน `topic_scan.py` กับชื่อเรื่องนั้น 1 ครั้งเพื่อตรวจว่าไม่ซ้ำงานล่าสุดและหาอ้างอิงได้พอ

### ขั้น 1 — สัมภาษณ์ก่อนเขียน

เรียกสกิล `grill-me` แล้วสัมภาษณ์ตาม `references/interview.md` ทีละคำถาม ทุกคำถามมีคำตอบที่แนะนำ ถ้าคำตอบหาได้เองจากเอกสารที่ผู้ใช้ให้ ให้หาเองแทนการถาม หยุดเมื่อได้ครบ: วารสารเป้าหมาย ประเภทบทความ ชื่อเรื่องร่าง ปัญหา/ช่องว่าง วัตถุประสงค์ ทฤษฎีหลัก หลักธรรม (โหมด MCU) **แหล่งค้นอ้างอิงที่จะใช้เพิ่มจาก TCI (คำถาม 12a)** ข้อมูลวิจัย (บทความวิจัย) ข้อมูลผู้เขียน องค์ความรู้ใหม่ที่อยากเสนอ บันทึกเป็น `brief.md` แล้วให้ผู้ใช้ยืนยัน

### ขั้น 2 — เก็บเกณฑ์วารสาร

- เปิดหน้า Author Guidelines ของวารสารเป้าหมายด้วย WebFetch และดาวน์โหลด template ถ้ามี สรุปเป็นตารางเกณฑ์ใน `brief.md` (วิธีละเอียดใน `general-journals.md`)
- โหมด MCU: ใช้ `mcu-journals.md` เป็นค่าเริ่มต้น แล้วแทนด้วยค่าของวารสารเป้าหมายเมื่อไม่ตรงกัน
- ดูตัวอย่าง: ค้นบทความที่ตีพิมพ์แล้วในวารสารเป้าหมายที่หัวข้อใกล้เคียง (ผ่าน `tci_search.py` หรือ WebSearch บน `tci-thaijo.org`) 1-2 เรื่อง เพื่อดูโครงและลีลาที่วารสารนั้นรับ

### ขั้น 3 — ค้นแหล่งอ้างอิง (อย่างน้อย 10 รายการ ตั้งเป้า 12-20)

แหล่งหลัก: ฐาน TCI (https://search.tci-thailand.org/advance_search.html) ผ่านสคริปต์:

```bash
python -I <skill-dir>/scripts/tci_search.py "ภาวะผู้นำ" "พรหมวิหาร" --size 15 --years 2021-2026 --abstract --json <workdir>/tci_raw.json
# --field title|keyword|article_abstract   --op and|or   --page 2
```

ใช้ Python เสมอ (curl บางสภาพแวดล้อม เช่น Git Bash บน Windows ส่งภาษาไทยผิด encoding ทำให้ได้ผลว่าง)

แหล่งเสริม — ค้นเฉพาะแหล่งที่ผู้ใช้เลือกในคำถาม 12a (ดู `brief.md`) ถ้าผู้ใช้เลือก "TCI อย่างเดียว" ให้ข้ามส่วนนี้:

```bash
# ฐานนานาชาติ/เฉพาะสาขา (ค้นเป็นภาษาอังกฤษ) — ชุดตามสาขาดู references/search-sources.md
python -I <skill-dir>/scripts/academic_search.py "digital leadership Brahmavihara" --sources openalex,crossref,doaj --size 8 --years 2021-2026 --abstract --json <workdir>/intl_raw.json
# ยืนยันรายการที่ได้จากแหล่งใดก็ได้ที่มี DOI
python -I <skill-dir>/scripts/academic_search.py --doi 10.xxxx/xxxxx
```
วิทยานิพนธ์/คลังปัญญาไทย และ ThaiJO ฉบับเต็ม: WebSearch `site:tdc.thailis.or.th`, `site:tci-thaijo.org` หรือ Google Scholar (https://scholar.google.com/) ตาม `search-sources.md`
ใช้หลักคัดกรองคุณภาพใน `search-sources.md` เสมอ (peer review, ระวัง preprint และวารสารล่าเหยื่อ, สัดส่วนงานไทย/ต่างประเทศตามที่ผู้ใช้กำหนด)

แนวทาง:
- ค้นหลายรอบ: ตัวแปรหลัก, ทฤษฎีหลัก, หลักธรรม, บริบท/พื้นที่, ศัพท์อังกฤษของแนวคิดเดียวกัน ลอง `--field keyword` และ `--field article_abstract` เมื่อชื่อเรื่องได้ผลน้อย
- เลือกความตรงประเด็นก่อน แล้วความใหม่ (เน้น 5 ปีล่าสุด เรื่องเดียวกันใช้รายการที่ใหม่ที่สุด) แล้วจำนวนครั้งที่ถูกอ้าง
- ผสมแหล่ง: บทความวารสารเป็นแกน + ตำรา/ทฤษฎีต้นฉบับ + งานต่างประเทศ โหมด MCU นับพระไตรปิฎกและตำราหลักธรรมได้ แต่ควรมีบทความวารสารไม่น้อยกว่า 8 รายการ
- ยืนยันทุกรายการอย่างน้อยหนึ่งทาง: ผล `tci_search.py`, `academic_search.py --doi`, เปิดหน้าบทความ, หรือไฟล์ที่ผู้ใช้มี แล้วบันทึกลง `refs.json` (เพิ่มช่อง `"source_db"` ว่ามาจากฐานใด):

```json
{"key": "สมชาย รักเรียน และคณะ, 2567", "lang": "th", "type": "journal",
 "authors": ["..."], "year_be": 2567, "year_ce": 2024, "title": "...", "journal": "...",
 "volume": "13", "issue": "4", "pages": "166-179", "url": "...",
 "verified_via": "tci_search <วันที่>", "use_for": "บทนำ: สภาพปัญหา", "key_point": "สาระ 1-2 บรรทัดจากบทคัดย่อ"}
```

- ใช้เฉพาะสาระที่อ่านจากบทคัดย่อ/เนื้อหาจริง ห้ามอ้างว่างานใด "พบว่า..." ถ้าไม่ได้อ่านข้อค้นพบนั้น
- **อ่านฉบับเต็มของงานที่ใช้เป็นหลักฐานหลัก** (ดาวน์โหลด PDF จากหน้าวารสารไว้ใน `fulltext/`) แล้วตรวจจำนวนตัวอย่าง ผู้ตอบ สิ่งที่วัด เกณฑ์นัยสำคัญ และข้อจำกัด บันทึก `"read": "fulltext"|"abstract"` ใน refs.json งานที่อ่านแล้วพบปัญหา (ไม่มีฉบับเต็ม บทคัดย่อไม่ตรงเนื้อใน สถิติขัดกัน) ให้ย้ายไป `refs-dropped.json` พร้อมเหตุผล
- บันทึกคำค้นจริง วันที่ค้น ช่วงปี จำนวนที่คัดกรอง/ไม่ซ้ำ/ตัดออก ลง `refs-log.md` ตั้งแต่รอบแรก บทความวิชาการเชิงทบทวนต้องใช้ข้อมูลนี้เขียนย่อหน้าวิธีการ (ดู `review-lessons.md` ข้อ ข)
- กฎหมายและมาตรการรัฐ: อ่านตัวบทจากราชกิจจานุเบกษา/เว็บหน่วยงาน อย่าอ้างจากข่าวอย่างเดียว
- ผู้แต่งที่เป็นพระสงฆ์ใช้ชื่อตามที่ปรากฏในบทความ
- แสดงตารางรายการที่คัดแล้ว (ผู้แต่ง ปี ชื่อเรื่อง ใช้ในส่วนใด) ให้ผู้ใช้ดูก่อนเดินหน้า

หลักการเขียน:
- ร้อยแก้ววิชาการไทย ย่อหน้าละหนึ่งประเด็น: ข้อความหลัก → หลักฐาน/อ้างอิง → การตีความของผู้เขียน ("ผู้เขียนเห็นว่า...") ดูแบบแผนใน `mcu-journals.md`
- ถ้อยคำต้องไม่แรงกว่าหลักฐาน: แยก "X พบว่า" / "X ระบุในส่วนอภิปรายว่า" / "ผู้เขียนอนุมานว่า" งานที่วัดการรับรู้อย่าเขียนเป็นผลจริง งานที่วัดคนละผลลัพธ์อย่าจับเป็นคู่ขัดแย้ง ข้ออ้าง "ไม่พบงาน" ผูกกับขอบเขตการค้น (รายละเอียด `review-lessons.md`)
- บทความวิชาการเชิงทบทวนที่เสนอกรอบแนวคิด: มีย่อหน้าวิธีการทบทวน ตารางสรุปงานเชิงประจักษ์ และระบุว่ากรอบแนวคิดยังไม่ผ่านการทดสอบ พร้อมข้อเสนอเป็นสมมติฐานและตัวชี้วัดสำหรับการวิจัยต่อไป
- บทคัดย่อ 300-400 คำ (วิชาการ 1 ย่อหน้า, วิจัย 2 ย่อหน้า) Abstract แปลจากบทคัดย่อของบทความนี้ตรงทุกประเด็น คำสำคัญ 3-5 คำ ตรงกันทั้งสองภาษา
- บทนำไม่เกิน 6 ย่อหน้า: ความเป็นมา → ปัญหา/ช่องว่าง (มีอ้างอิง) → ทฤษฎีที่ใช้ → นำสู่วัตถุประสงค์
- อ้างอิงกระจายทั่วบทความ ใช้ทั้ง `ชื่อ นามสกุล (2567)` และ `(ชื่อ นามสกุล, 2567)`
- ถอดความด้วยภาษาของผู้เขียน ห้ามคัดลอกยาว (เกณฑ์ความซ้ำ 15-25% ตามวารสาร และ ≤ 5% ต่อแหล่ง) คำพูดตรงจากพระไตรปิฎกสั้นและอยู่ในเครื่องหมายคำพูด
- ความยาว 8-15 หน้า A4 (TH Sarabun PSK 16) ประมาณ 4,000-7,000 คำ
- ใช้เลขอารบิกทั้งเรื่อง ปีในเนื้อหาภาษาไทยใช้ พ.ศ.

ให้ผู้ตรวจอิสระที่ไม่ได้เขียนบทความ (subagent ใหม่ หรือเครื่องมือ AI อื่นที่ผู้ใช้มี เช่น Codex CLI แบบอ่านอย่างเดียว) ทำหน้าที่กองบรรณาธิการ + ผู้ทรงคุณวุฒิ 2-3 ท่าน ตามกระบวนการพิจารณาของวารสาร ให้ข้อมูล: draft.md, PDF, ภาพ, refs.json, โฟลเดอร์ fulltext, เกณฑ์วารสาร และ `review-lessons.md` เป็นเกณฑ์

- รอบแรก: ให้ตรวจรูปแบบตามคำแนะนำผู้เขียน ความถูกต้องของการอ้างอิงเทียบกับฉบับเต็ม (สุ่มเลขหน้า ข้อความยกตรง ตัวเลข) ตรรกะ และความใหม่ แล้วตัดสิน ยอมรับ / แก้ไขเล็กน้อย / แก้ไขมาก / ปฏิเสธ พร้อมตาราง "สิ่งที่ต้องแก้" (ลำดับ | ตำแหน่ง | ปัญหา | หลักฐาน | สิ่งที่ต้องแก้ | ระดับ)

### ขั้น 10 — สร้างไฟล์ .docx

```bash
python -I <skill-dir>/scripts/build_docx.py <workdir>/draft.md <workdir>/<ชื่อ>.docx
```

ค่าเริ่มต้น (`--profile mcu`): A4 ขอบ 1 นิ้ว TH Sarabun PSK ประเภท 12 / ชื่อไทย 20 / ชื่ออังกฤษ 18 / ผู้เขียน 14 / หัวข้อ 18 / เนื้อหา 16 / ตาราง 14 pt ย่อหน้า 1.27 ซม. single spacing เนื้อหาจัดแบบ Thai Distributed (`--align justify|left`) อ้างอิงแบบ hanging indent ไม่ใส่เลขหน้า ฝังภาพจาก `figures/` พร้อมคำบรรยาย
โหมดทั่วไป: ปรับให้ตรงต้นแบบของวารสารด้วยตัวเลือก
- ขนาด/ฟอนต์: `--profile general --font ... --body-size --heading-size --title-size --title-en-size --title-en-upper yes|no --indent-cm --align justify|thai|left`
- ส่วนหัว: `--header-style left` (ชื่อเรื่องกึ่งกลาง ผู้เขียน/สังกัด/อีเมลชิดซ้าย) และ `--split-en-header` (ชื่อเรื่อง/ผู้เขียนอังกฤษขึ้นหน้าใหม่ก่อน Abstract)
- หน้า: `--page-numbers top-right|bottom-center`, `--page-break-before "บทนำ|References|..."`, `--center-headings "Abstract"`
- ภาพ/ตาราง: `--caption-align left`, `--table-style horizontal` (ไม่มีเส้นคอลัมน์)
- `--thai-wordbreak auto|on|off` แทรกตัวตัดคำไทยที่มองไม่เห็น (ต้องมี `pythainlp`) เพื่อให้ Word ตัดบรรทัดภาษาไทยถูกแม้เครื่องไม่มีตัวตัดคำไทย (ถ้าไม่มี บรรทัดจะขาดเฉพาะที่ช่องว่างและเกิดช่องโหว่ยาว) ถ้าเห็นคำถูกตัดกลางคำใน PDF (เช่น ตัวชี้ / วัด) ให้เพิ่มคำนั้นในไฟล์คำ บรรทัดละคำ แล้วส่ง `--thai-dict words.txt`
ถ้าวารสารมี template .docx ของตนเอง ให้เทเนื้อหาลง template ด้วยสกิล `docx`

ตัวอย่าง (วารสารที่กำหนด TH Sarabun New 18/16, ผู้เขียนชิดซ้าย, เลขหน้าขวาบน, บทนำและอ้างอิงขึ้นหน้าใหม่):
```bash
python -I <skill-dir>/scripts/build_docx.py draft.md out.docx --profile general --font "TH Sarabun New" --title-size 18 --title-en-size 18 --title-en-upper no --heading-size 16 --align justify --header-style left --split-en-header --page-numbers top-right --page-break-before "บทนำ|References|เอกสารอ้างอิงภาษาไทย" --caption-align left --table-style horizontal
```
การจัดแนวหัวข้อ (เช่น Abstract) ให้ยึดข้อกำหนดเป็นลายลักษณ์อักษรของวารสาร ถ้าแม่แบบจัดต่างจากข้อกำหนด ให้ใช้ `--center-headings` เฉพาะเมื่อข้อกำหนดสั่งให้จัดกึ่งกลาง
วารสารที่ให้การอ้างอิงเป็นภาษาอังกฤษทั้งหมด: ใช้ชื่อภาษาอังกฤษของงานไทยจาก TCI/ThaiJO (`title_en`, `authors_en`, `journal_en` ใน refs.json) ใส่ `[in Thai]` และแนบรายการภาษาไทยแยกเป็นหัวข้อ `# เอกสารอ้างอิงภาษาไทย ...` ถ้าวารสารขอ

ตรวจหน้าตาและนับหน้า: แปลง .docx เป็น PDF (LibreOffice `soffice --headless --convert-to pdf` หรือ Microsoft Word ผ่าน COM บน Windows) แล้วเรนเดอร์หน้าเป็น PNG (เช่น `pypdfium2`) เพื่อดู ถ้าเครื่องไม่มีฟอนต์ที่วารสารกำหนด ตัวอักษรจะถูกแทนและจำนวนหน้าคลาดเคลื่อน ให้แนะนำผู้ใช้ติดตั้งฟอนต์ก่อนนับหน้าจริง ระหว่างนั้นประมาณด้วยฟอนต์ไทยที่มีในเครื่อง (เช่น Angsana New) และบอกว่าเป็นค่าประมาณ (ไฟล์ยังระบุฟอนต์ถูกต้อง) บน Windows ถ้าเรียก PowerShell ผ่านสคริปต์ไม่ได้ ให้เรียก Word COM เป็นคำสั่งบรรทัดเดียวในเครื่องมือ PowerShell โดยตรง บน Mac ใช้ Word for Mac ผ่าน AppleScript (`osascript`) ได้ (ใช้ TH SarabunPSK ที่มากับ Word แทนฟอนต์ที่ไม่มีในสำเนาที่แปลงได้) แต่ Word ถูก sandbox: ไฟล์ต้องอยู่ในโฟลเดอร์ที่ผู้ใช้ให้สิทธิ์แล้ว และถ้ามีหน้าต่าง "Grant File Access" ผู้ใช้ต้องกดเอง ไม่ควรใช้ LibreOffice นับหน้าเอกสารไทยถ้าไม่มีฟอนต์ที่กำหนด เพราะมันแทนด้วยฟอนต์อื่นและจำนวนหน้าคลาดได้เกือบเท่าตัว ก่อนเชื่อจำนวนหน้าจากเครื่องหรือวิธีใหม่ ให้แปลงฉบับเก่าที่รู้จำนวนหน้าแล้วเทียบก่อนทุกครั้ง

สุดท้ายสรุปให้ผู้ใช้: ที่อยู่ไฟล์ จำนวนหน้าโดยประมาณ จำนวนอ้างอิง (ไทย/อังกฤษ) สิ่งที่ยังต้องเติมหรือตรวจเอง (ชื่อผู้เขียน อีเมล ความซ้ำ เลขพระไตรปิฎกที่ยังยืนยันไม่ได้) และขั้นตอนส่งผ่านระบบของวารสาร

## ข้อควรระวัง

- ใช้วันที่ปัจจุบันตัดสินความใหม่ของอ้างอิง ปี ค.ศ. + 543 = พ.ศ.
- ถ้า TCI ค้นไม่ได้ (เว็บล่มหรือเปลี่ยนระบบ) ให้ใช้ WebSearch จำกัดโดเมน `tci-thaijo.org` หรือเปิดหน้า advance search ด้วยเบราว์เซอร์ แล้วแจ้งผู้ใช้
- ให้ผู้ใช้อนุมัติที่จุดสำคัญ: brief, รายการอ้างอิง, outline, draft สุดท้าย ไม่ต้องขออนุมัติทุกย่อหน้า
