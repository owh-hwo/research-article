# Research Article Writer (บทความวิจัย / บทความวิชาการ)

สกิลนี้พาผู้เขียนจาก "หัวข้อที่สนใจ" ไปจนถึง "ไฟล์ .docx พร้อมส่งวารสาร" โดยยึดหลัก 3 ข้อที่ห้ามละเมิด

1. **อ้างอิงต้องมีจริงและตรวจได้** ทุกรายการต้องค้นและเปิดดูข้อมูลจริง (TCI, ThaiJO, เว็บวารสาร, DOI, หนังสือที่ผู้ใช้มี) ห้ามแต่งชื่อผู้แต่ง ชื่อเรื่อง ปี เลขหน้า หรือ URL ถ้าตรวจไม่ได้ให้ตัดทิ้งและหาใหม่
2. **อ้างอิงอย่างน้อย 10 แหล่ง** ทั้งสองโหมด ทุกรายการที่อ้างในเนื้อหาต้องอยู่ท้ายเรื่อง และกลับกัน
3. **ห้ามสร้างข้อมูลวิจัยขึ้นเอง** ผลการวิจัย ตัวเลข กลุ่มตัวอย่าง คำสัมภาษณ์ ต้องมาจากผู้เขียนเท่านั้น ถ้ายังไม่มี ให้เว้น `[รอข้อมูล: ...]` แล้วแจ้งผู้ใช้

- `diagram-design` — สร้างแผนภาพ HTML/SVG/PNG (ขั้น 7) ถ้าไม่มี ให้สร้าง SVG/HTML เองแล้วแปลงเป็น PNG
- `thai-humanizer` (**จำเป็น** สำหรับขั้น 6, 8, 9; https://github.com/owh-hwo/thai-humanizer ติดตั้งมาพร้อม research-article อัตโนมัติเมื่อติดตั้งแบบ plugin ถ้าไม่มี ให้ติดตั้งด้วย `/plugin marketplace add owh-hwo/thai-humanizer` แล้ว `/plugin install thai-humanizer@thai-humanizer`) — แม่แบบย่อหน้าภาษาไทยวิชาการ (`references/thai-prose-patterns.md`) ร่องรอยภาษา AI/สำนวนแปล (`references/thai-humanizer.md`) สคริปต์นับร่องรอย (`scripts/thai_style_check.py`) และ Humanizer ภาษาอังกฤษรวมอยู่ด้วย ด้านล่างเรียกโฟลเดอร์ของสกิลนี้ว่า `<thai-humanizer-dir>` ถ้ายังไม่ได้ติดตั้ง ให้บอกผู้ใช้ก่อนเริ่มขั้น 6
- `docx` — แก้ไข .docx ขั้นสูงหรือเทเนื้อหาลง template ของวารสาร

## พื้นที่ทำงานของแต่ละบทความ

ถามผู้ใช้ว่าจะเก็บงานที่ใด ถ้าไม่ระบุ ใช้ `./articles/<ชื่อย่อบทความ>/` ในไดเรกทอรีปัจจุบัน

```
fulltext/         ฉบับเต็ม PDF/ข้อความของแหล่งที่อ่าน (ขั้น 3)
refs-dropped.json รายการที่ตัดออกพร้อมเหตุผล
response-to-reviewers.md  ตารางตอบผู้ตรวจแต่ละรอบ (ขั้น 9.5)
reviews/roundN/   ผลตรวจแยกบทบาท <role>.md และภาพหน้า PDF ใน pages/ (ขั้น 9.5)
review-roundN.md  รายงานรวมของรอบนั้นโดยกองบรรณาธิการ (ขั้น 9.5)
topic-options.md  ตัวเลือกหัวข้อ ผลสแกน คะแนน (ขั้น 0.5)
brief.md          หัวข้อที่เลือก ผลการสัมภาษณ์ และเกณฑ์วารสาร (ขั้น 0.5-2)
refs.json         รายการอ้างอิงที่ตรวจแล้ว (ขั้น 3-4)
refs-log.md       บันทึกการค้น: คำค้น ผลที่ได้ เหตุผลที่เลือก/ตัด
outline.md        โครงเรื่อง + งบอักขระต่อหัวข้อ + ย่อหน้าห้ามตัด (ขั้น 5)
terms.json        คำหลักไทย/อังกฤษ/คำย่อ และรูปแปรที่ห้ามใช้ (ขั้น 6; check_terms.py)
draft.md          ต้นฉบับ (ขั้น 6-8)
figures/          แผนภาพ .html + .png (ขั้น 7)
<ชื่อ>.docx       ไฟล์ส่งวารสาร (ขั้น 10)
checklist.md      ผลตรวจก่อนส่ง (ขั้น 9)
```

ถ้าผู้ใช้มีเอกสารของตนเอง (คำแนะนำผู้เขียนของวารสาร, template, บทความตัวอย่าง, คู่มือหลักธรรมของหลักสูตร, งานวิจัยที่อยากอ้าง) ให้ขอ path/ลิงก์แล้วอ่านก่อนเริ่ม เก็บข้อความที่สกัดได้ไว้ในโฟลเดอร์งานของบทความนั้น

## ขั้นตอนการทำงาน

### ขั้น 0 — เลือกโหมด

ถามผู้ใช้ (AskUserQuestion) ถ้ายังไม่ได้บอก:
- **โหมด MCU** — วารสารสายพุทธบูรณาการ (เช่น วารสารในเครือ มหาวิทยาลัยมหาจุฬาลงกรณราชวิทยาลัย) ต้องบูรณาการหลักพุทธธรรมและอ้างพระไตรปิฎก
- **โหมดทั่วไป** — วารสารอื่น ไม่บังคับหลักธรรม (ใส่ได้ถ้าผู้เขียนต้องการ) ใช้เกณฑ์ของวารสารเป้าหมาย

และถามประเภท: บทความวิจัย หรือ บทความวิชาการ

### ขั้น 0.5 — ช่วยเลือกหัวข้อ (เมื่อยังไม่มีชื่อเรื่องชัด)

ถ้าผู้ใช้บอกแค่เนื้อหาหลัก/เรื่องที่สนใจ หรือขอให้ช่วยหาหัวข้อ ให้ทำตาม `references/topic-ideation.md`:
1. รับวัตถุดิบ (เล่าอิสระหรือไฟล์) ถามเสริมเฉพาะที่ขาด
2. แตกองค์ประกอบ: ตัวแปร บริบท ทฤษฎี หลักธรรม มุมร่วมสมัย ผลลัพธ์
3. สร้างหัวข้อ 5-8 ตัวเลือกตามแบบแผนชื่อเรื่อง (ปลอดภัย / มุมใหม่ / ทำได้เร็ว)
4. สแกนทุกตัวเลือกด้วย `topic_scan.py` และอ่านตัวอย่างงานล่าสุดเพื่อตัดหัวข้อที่ซ้ำกับงานที่มีอยู่
5. ให้คะแนน (ความใหม่ ความพอของอ้างอิง ความเป็นไปได้ ขอบเขตวารสาร ความทันสมัย) เสนอ 3 อันดับพร้อมชื่อไทย/อังกฤษ ปัญหา วัตถุประสงค์ร่าง ทฤษฎี/หลักธรรม ข้อมูลที่ต้องมี ความเสี่ยง
6. ให้ผู้ใช้เลือก แล้วบันทึกลง `brief.md` และ `topic-options.md` ก่อนเข้าขั้น 1 (ข้ามคำถามที่ได้คำตอบแล้ว)

ถ้าผู้ใช้มีชื่อเรื่องอยู่แล้ว ยังควรรัน `topic_scan.py` กับชื่อเรื่องนั้น 1 ครั้งเพื่อตรวจว่าไม่ซ้ำงานล่าสุดและหาอ้างอิงได้พอ

### ขั้น 1 — สัมภาษณ์ก่อนเขียน

เรียกสกิล `grill-me` แล้วสัมภาษณ์ตาม `references/interview.md` ทีละคำถาม ทุกคำถามมีคำตอบที่แนะนำ ถ้าคำตอบหาได้เองจากเอกสารที่ผู้ใช้ให้ ให้หาเองแทนการถาม หยุดเมื่อได้ครบ: วารสารเป้าหมาย ประเภทบทความ ชื่อเรื่องร่าง ปัญหา/ช่องว่าง วัตถุประสงค์ ทฤษฎีหลัก หลักธรรม (โหมด MCU) **แหล่งค้นอ้างอิงที่จะใช้เพิ่มจาก TCI (คำถาม 12a)** ข้อมูลวิจัย (บทความวิจัย) ข้อมูลผู้เขียน องค์ความรู้ใหม่ที่อยากเสนอ บันทึกเป็น `brief.md` แล้วให้ผู้ใช้ยืนยัน

### ขั้น 2 — เก็บเกณฑ์วารสาร

- เปิดหน้า Author Guidelines ของวารสารเป้าหมายด้วย WebFetch และดาวน์โหลด template ถ้ามี สรุปเป็นตารางเกณฑ์ใน `brief.md` (วิธีละเอียดใน `general-journals.md`)
- โหมด MCU: ใช้ `mcu-journals.md` เป็นค่าเริ่มต้น แล้วแทนด้วยค่าของวารสารเป้าหมายเมื่อไม่ตรงกัน
- ดูตัวอย่าง: ค้นบทความที่ตีพิมพ์แล้วในวารสารเป้าหมายที่หัวข้อใกล้เคียง (ผ่าน `tci_search.py` หรือ WebSearch บน `tci-thaijo.org`) 1-2 เรื่อง เพื่อดูโครงและลีลาที่วารสารนั้นรับ

### ขั้น 3 — ค้นแหล่งอ้างอิง (อย่างน้อย 10 รายการ ตั้งเป้า 12-20)

```bash
python -I <skill-dir>/scripts/tci_search.py "ภาวะผู้นำ" "พรหมวิหาร" --size 15 --years 2021-2026 --abstract --json <workdir>/tci_raw.json
# --field title|keyword|article_abstract   --op and|or   --page 2
```

ใช้ Python เสมอ (curl บางสภาพแวดล้อม เช่น Git Bash บน Windows ส่งภาษาไทยผิด encoding ทำให้ได้ผลว่าง)

แหล่งเสริม — ค้นเฉพาะแหล่งที่ผู้ใช้เลือกในคำถาม 12a (ดู `brief.md`) ถ้าผู้ใช้เลือก "TCI อย่างเดียว" ให้ข้ามส่วนนี้:

วิทยานิพนธ์/คลังปัญญาไทย และ ThaiJO ฉบับเต็ม: WebSearch `site:tdc.thailis.or.th`, `site:tci-thaijo.org` หรือ Google Scholar (https://scholar.google.com/) ตาม `search-sources.md`
ใช้หลักคัดกรองคุณภาพใน `search-sources.md` เสมอ (peer review, ระวัง preprint และวารสารล่าเหยื่อ, สัดส่วนงานไทย/ต่างประเทศตามที่ผู้ใช้กำหนด)

แนวทาง:
- ค้นหลายรอบ: ตัวแปรหลัก, ทฤษฎีหลัก, หลักธรรม, บริบท/พื้นที่, ศัพท์อังกฤษของแนวคิดเดียวกัน ลอง `--field keyword` และ `--field article_abstract` เมื่อชื่อเรื่องได้ผลน้อย
- เลือกความตรงประเด็นก่อน แล้วความใหม่ (เน้น 5 ปีล่าสุด เรื่องเดียวกันใช้รายการที่ใหม่ที่สุด) แล้วจำนวนครั้งที่ถูกอ้าง
- ผสมแหล่ง: บทความวารสารเป็นแกน + ตำรา/ทฤษฎีต้นฉบับ + งานต่างประเทศ โหมด MCU นับพระไตรปิฎกและตำราหลักธรรมได้ แต่ควรมีบทความวารสารไม่น้อยกว่า 8 รายการ
- ยืนยันทุกรายการอย่างน้อยหนึ่งทาง: ผล `tci_search.py`, `academic_search.py --doi`, เปิดหน้าบทความ, หรือไฟล์ที่ผู้ใช้มี แล้วบันทึกลง `refs.json` (เพิ่มช่อง `"source_db"` ว่ามาจากฐานใด):

```json
{"key": "<ชื่อผู้แต่ง> และคณะ, <ปี>", "lang": "th", "type": "journal",
 "authors": ["..."], "year_be": 2567, "year_ce": 2024, "title": "...", "journal": "...",
 "volume": "13", "issue": "4", "pages": "166-179", "url": "...",
 "verified_via": "tci_search <วันที่>", "use_for": "บทนำ: สภาพปัญหา",
 "read": "fulltext|abstract|bibliographic", "fulltext": "fulltext/<ไฟล์>.pdf",
 "key_point": "ใคร ศึกษาอะไร กับใคร/ข้อมูลอะไร วัดอะไร ได้ผลอย่างไร (โน้ตภาษาไทย 1-2 บรรทัด รวมตัวเลขทุกตัวที่จะอ้าง)",
 "cite_scope": "อ้างได้แค่ไหน: วัดความตั้งใจไม่ใช่การใช้จริง / เป็นการตีความ ไม่ได้ทดสอบ / ห้ามอ้างตัวเลข X เพราะ…"}
```

สามช่องท้ายคือสัญญาว่าร่างจะเขียนได้แค่ไหน `check_claims.py` (ขั้น 6, 9) ใช้ช่องเหล่านี้ตรวจร่าง: ตัวเลขที่ไม่อยู่ใน `key_point` คำว่า "พบว่า" กับแหล่งที่ `read` เป็น `abstract` และประโยคที่เขียนเป็นผลจริงทั้งที่ `cite_scope` บอกว่าวัดความตั้งใจ จะถูกชี้ทั้งหมด จึงต้องกรอกให้ครบตั้งแต่ขั้นนี้ ไม่ใช่ย้อนมาเติมตอนผู้ตรวจพบ

- **`key_point` เขียนเป็นโน้ตภาษาไทยเสมอ แม้แหล่งเป็นภาษาอังกฤษ** ในรูป "ใคร ศึกษาอะไร กับใคร/ข้อมูลอะไร วัดอะไร ได้ผลอย่างไร" ไม่ใช่แปลบทคัดย่อประโยคต่อประโยค ขั้น 6 จะเขียนจากโน้ตนี้โดยไม่เปิดต้นฉบับอังกฤษ สำนวนแปลส่วนใหญ่เกิดจากการมองประโยคอังกฤษขณะเขียนไทย (ดู `<thai-humanizer-dir>/references/thai-prose-patterns.md` หลักข้อ 1)

- ใช้เฉพาะสาระที่อ่านจากบทคัดย่อ/เนื้อหาจริง ห้ามอ้างว่างานใด "พบว่า..." ถ้าไม่ได้อ่านข้อค้นพบนั้น
- **อ่านฉบับเต็มของงานที่ใช้เป็นหลักฐานหลัก** (ดาวน์โหลด PDF จากหน้าวารสารไว้ใน `fulltext/`) แล้วตรวจจำนวนตัวอย่าง ผู้ตอบ สิ่งที่วัด เกณฑ์นัยสำคัญ และข้อจำกัด บันทึก `"read": "fulltext"|"abstract"` ใน refs.json งานที่อ่านแล้วพบปัญหา (ไม่มีฉบับเต็ม บทคัดย่อไม่ตรงเนื้อใน สถิติขัดกัน) ให้ย้ายไป `refs-dropped.json` พร้อมเหตุผล
- บันทึกคำค้นจริง วันที่ค้น ช่วงปี จำนวนที่คัดกรอง/ไม่ซ้ำ/ตัดออก ลง `refs-log.md` ตั้งแต่รอบแรก ด้วย `python -I <skill-dir>/scripts/make_refs_log.py <workdir>` (ตั้งชื่อไฟล์ผลค้นให้บอกคำค้น เช่น `tci_ภาษี_ดิจิทัล.json`, `intl_tax_compliance_cost.json` สคริปต์อนุมานคำค้นจากชื่อไฟล์แล้วให้ตรวจ) รันซ้ำทุกครั้งที่ตัดแหล่ง (`refs-dropped.json` ต้องมี `drop_reason`) บทความวิชาการเชิงทบทวนต้องใช้ตัวเลขจากไฟล์นี้เขียนย่อหน้าวิธีการ (ดู `review-lessons.md` ข้อ ข) ไม่เขียนยอดจากความจำ
- กฎหมายและมาตรการรัฐ: อ่านตัวบทจากราชกิจจานุเบกษา/เว็บหน่วยงาน อย่าอ้างจากข่าวอย่างเดียว **ทุกมาตรา/ข้อที่จะอ้างต้องมีตัวบท (PDF ภาพ หรือข้อความ) ใน `fulltext/` และระบุใน `"fulltext"` ก่อนเริ่มขั้น 6** รวมประมวลกฎหมายหลักที่อ้างมาตราด้วย ไม่ใช่เฉพาะกฎหมายลำดับรอง ถ้าหาตัวบทไม่ได้ อย่าสรุปเงื่อนไขของมาตรานั้นในร่าง ให้อ้างเพียงว่ามีบทบัญญัติเรื่องใด ผู้ตรวจจะเทียบถ้อยคำกฎหมายกับตัวบททุกรอบ และการย่อความยาวภายหลังต้องเทียบตัวบทซ้ำ ซึ่งทำไม่ได้ถ้าไม่มีไฟล์
- ผู้แต่งที่เป็นพระสงฆ์ใช้ชื่อตามที่ปรากฏในบทความ
- แสดงตารางรายการที่คัดแล้ว (ผู้แต่ง ปี ชื่อเรื่อง ใช้ในส่วนใด) ให้ผู้ใช้ดูก่อนเดินหน้า

### ขั้น 5 — โครงเรื่อง

เขียน `outline.md` ตามโครงสร้างของวารสาร ใต้แต่ละหัวข้อใส่: ประเด็นของย่อหน้า + อ้างอิงที่จะใช้ (key จาก refs.json) + **งบความยาวเป็นอักขระ** ตรวจว่าทุกรายการใน refs.json มีที่ใช้ ให้ผู้ใช้อนุมัติก่อนเขียนจริง

**งบความยาวตั้งตั้งแต่ตอนนี้ ไม่ใช่ตอนไฟล์เกิน** ความยาวเกินเพดานเป็นสาเหตุการแก้ซ้ำที่ใหญ่ที่สุดรองจากหลักฐานเกินแหล่ง และการตัดตอนท้ายทำลายสายหลักฐาน (ตัดย่อหน้าที่บทคัดย่อพึ่ง ตัดเงื่อนไขกฎหมาย) วิธีตั้งงบ:
1. อ่านเพดานหน้าจาก `brief.md` และวิธีนับของวารสาร (รวมอ้างอิงหรือไม่ รายการภาษาไทยที่แนบนับหรือไม่) ไม่ชัดให้ใช้แบบที่เข้มกว่า
2. ประมาณจากค่าที่สอบเทียบกับบทความจริง (TH Sarabun 16 pt A4 ขอบ 1 นิ้ว): ร้อยแก้วราว **2,100 อักขระไทยต่อหน้า** (รวมหัวข้อ) แถวตารางที่มีเซลล์หลายบรรทัดราว 0.06 หน้าต่อแถว ภาพกว้างเต็มคอลัมน์ราว 0.4 หน้า รายการอ้างอิงราว 9 รายการต่อหน้า (ถ้าวารสารให้แนบรายการภาษาไทยซ้ำ นับสองเท่า) `check_claims.py --pages N` คำนวณให้
3. แจกงบลงหัวข้อใน outline ให้รวมแล้ว **ต่ำกว่าเพดานราว 10%** เพื่อเหลือที่ให้ผู้ตรวจขอเพิ่ม และทำเครื่องหมายย่อหน้าที่ **ห้ามตัดในรอบย่อ**: ย่อหน้ากฎหมาย ย่อหน้าวิธีการทบทวน และย่อหน้าที่เป็นฐานของข้อเสนอ/ข้อสรุปในบทคัดย่อ
4. ถ้างบไม่พอกับประเด็นที่วางไว้ ให้ลดจำนวนประเด็นหรือแหล่งตั้งแต่ขั้นนี้ ไม่ใช่เขียนให้ครบแล้วค่อยหั่น

### ขั้น 6 — เขียนต้นฉบับ `draft.md`

รูปแบบไฟล์ (ใช้กับ `build_docx.py`):

```markdown

## หัวข้อย่อย (ถ้ามี)

![ภาพที่ 1 ชื่อภาพ](figures/fig1.png)

รายการละหนึ่งย่อหน้า คั่นด้วยบรรทัดว่าง
```

หลักการเขียน:
- **อ่าน `<thai-humanizer-dir>/references/thai-prose-patterns.md` ก่อนเริ่มร่าง** เลือกแม่แบบย่อหน้า (ก-ญ) ให้แต่ละย่อหน้าใน outline แล้วเขียนจากโน้ตภาษาไทยใน `key_point` ของ refs.json ห้ามเปิดบทคัดย่อหรือข้อความภาษาอังกฤษของแหล่งไว้ขณะเขียนย่อหน้า เขียนเสร็จค่อยกลับไปเทียบตัวเลขและระดับความมั่นใจกับต้นฉบับ
- **ทุกประโยคที่อ้างแหล่งต้องเขียนได้จาก `key_point` + `cite_scope` ของแหล่งนั้นเท่านั้น** ถ้าอยากเขียนสิ่งที่ไม่อยู่ในโน้ต ให้กลับไปอ่านแหล่งแล้วเติมโน้ตก่อน (ไม่ใช่เขียนจากความจำ) ระดับคำกริยาต้องตรงกับ `read`: `fulltext` → "พบว่า/รายงานว่า", `abstract` → "บทคัดย่อของ … รายงานว่า", `bibliographic` → ห้ามบรรยายเนื้อหา และถ้า `cite_scope` บอกว่าวัดความตั้งใจ/การรับรู้ หรือเป็นการตีความที่ไม่ได้ทดสอบ ประโยคต้องมีคำบอกระดับนั้น นี่คือสิ่งที่ผู้ตรวจจับได้มากที่สุด (ราวหนึ่งในสามของข้อแก้ทั้งหมดในบทความที่ผ่านมา) และ `check_claims.py` ตรวจให้ก่อนผู้ตรวจเห็น
- **เขียนตามงบใน outline** ย่อหน้าใดเกินงบให้ตัดตอนเขียน ไม่ยกยอดไปตัดตอนท้าย เมื่อร่างครบทุกหัวข้อแล้ว **สร้าง .docx + นับหน้าทันที (ขั้น 10 ส่วนสร้างไฟล์) ก่อนเกลาภาษาและก่อนเรียกผู้ตรวจ** ถ้าเกินเพดาน ให้ตัดตั้งแต่ตรงนี้ตามลำดับ: ประโยคซ้ำ/รายชื่อหัวข้อ → ตัวอย่างเสริม → แหล่งที่ซ้ำประเด็นกับแหล่งอื่น (ย้ายไป `refs-dropped.json` พร้อมเหตุผล) ห้ามแตะย่อหน้าที่ outline ทำเครื่องหมายห้ามตัด และหลังตัดทุกครั้งให้รัน `check_claims.py` แล้วอ่านบทคัดย่อซ้ำว่าทุกข้อเสนอยังมีย่อหน้ารองรับ
- ร้อยแก้ววิชาการไทย ย่อหน้าละหนึ่งประเด็น: ข้อความหลัก → หลักฐาน/อ้างอิง → การตีความของผู้เขียน ("ผู้เขียนเห็นว่า...") ดูแบบแผนใน `mcu-journals.md`
- ข้อความที่คัดจากตัวบทกฎหมาย คำนิยามทางการ หรือข้อความยกตรง ให้ครอบด้วย `[ตัวบท]...[/ตัวบท]` ขั้น 8 และ `thai_style_check.py` ของสกิล thai-humanizer จะไม่แตะ และ `build_docx.py` ลบป้ายให้ตอนสร้างไฟล์
- เขียนบทคัดย่อภาษาไทยให้เสร็จก่อน แล้วจึงแปลเป็น Abstract ทีละประเด็น ห้ามร่าง Abstract ภาษาอังกฤษก่อนแล้วแปลกลับเป็นไทย
- เขียนจบแต่ละหัวข้อใหญ่ ให้รัน `python -I <thai-humanizer-dir>/scripts/thai_style_check.py draft.md` และ `python -I <skill-dir>/scripts/check_claims.py draft.md refs.json` ดูร่องรอยและข้ออ้างที่เกินโน้ตก่อนไปหัวข้อถัดไป แก้ตอนนี้ถูกกว่าแก้ตอนท้าย
- **คำหลักคำเดียวตลอดเรื่อง**: ทำ `terms.json` (คำไทย คำอังกฤษ คำย่อ รูปแปรที่ห้ามใช้ ที่ที่ต้องปรากฏ) ตั้งแต่เริ่มร่าง แล้วรัน `python -I <skill-dir>/scripts/check_terms.py draft.md terms.json` หลังจบแต่ละหัวข้อและหลังทำภาพ (ขั้น 7) สคริปต์อ่านข้อความใน `figures/*.html` ด้วย ศัพท์ที่ต่างกันระหว่างเนื้อหา ภาพ ตาราง และบทคัดย่อสองภาษาเป็นกลุ่มข้อแก้ที่ใหญ่เป็นอันดับสองในบทความที่ผ่านมา
- **รายการอ้างอิงท้ายเรื่องสร้างจาก refs.json ด้วย `make_reflist.py`** ไม่เขียนมือและไม่เขียนสคริปต์ใหม่ต่อบทความ: `--style th-apa` (วารสารไทยทั่วไป/มจร: ไทยก่อน อังกฤษตาม) หรือ `--style en-apa` (วารสารที่ให้อ้างเป็นอังกฤษทั้งหมด: `references_en.md` + รายการไทยแยก `references_th.md`) ใส่ `--write-keys` ครั้งแรกเพื่อเติม `key_th`/`cite_en` ที่สคริปต์ตรวจใช้จับคู่ ข้อมูลที่รายการต้องการ (ผู้จัดพิมพ์ วันที่ประกาศ ราชกิจจานุเบกษา `url_in_ref`) ต้องอยู่ใน refs.json ไม่แก้ที่ไฟล์ผล แล้วต่อท้าย draft.md ด้วยหัวข้ออ้างอิงตามวารสาร
- ถ้อยคำต้องไม่แรงกว่าหลักฐาน: แยก "X พบว่า" / "X ระบุในส่วนอภิปรายว่า" / "ผู้เขียนอนุมานว่า" งานที่วัดการรับรู้อย่าเขียนเป็นผลจริง งานที่วัดคนละผลลัพธ์อย่าจับเป็นคู่ขัดแย้ง ข้ออ้าง "ไม่พบงาน" ผูกกับขอบเขตการค้น (รายละเอียด `review-lessons.md`)
- บทความวิชาการเชิงทบทวนที่เสนอกรอบแนวคิด: มีย่อหน้าวิธีการทบทวน ตารางสรุปงานเชิงประจักษ์ และระบุว่ากรอบแนวคิดยังไม่ผ่านการทดสอบ พร้อมข้อเสนอเป็นสมมติฐานและตัวชี้วัดสำหรับการวิจัยต่อไป
- บทคัดย่อ 300-400 คำ (วิชาการ 1 ย่อหน้า, วิจัย 2 ย่อหน้า) Abstract แปลจากบทคัดย่อของบทความนี้ตรงทุกประเด็น คำสำคัญ 3-5 คำ ตรงกันทั้งสองภาษา
- บทนำไม่เกิน 6 ย่อหน้า: ความเป็นมา → ปัญหา/ช่องว่าง (มีอ้างอิง) → ทฤษฎีที่ใช้ → นำสู่วัตถุประสงค์
- อ้างอิงกระจายทั่วบทความ ใช้ทั้ง `ชื่อ นามสกุล (2567)` และ `(ชื่อ นามสกุล, 2567)`
- ถอดความด้วยภาษาของผู้เขียน ห้ามคัดลอกยาว (เกณฑ์ความซ้ำ 15-25% ตามวารสาร และ ≤ 5% ต่อแหล่ง) คำพูดตรงจากพระไตรปิฎกสั้นและอยู่ในเครื่องหมายคำพูด
- ความยาวตามเพดานของวารสาร (ทั่วไป 8-16 หน้า A4 TH Sarabun 16) ใช้งบอักขระจากขั้น 5 ไม่ใช้จำนวนคำ เพราะตัวนับคำภาษาไทยให้ค่าต่างกันมาก
- ใช้เลขอารบิกทั้งเรื่อง ปีในเนื้อหาภาษาไทยใช้ พ.ศ.

### ขั้น 7 — แผนภาพประกอบ

ส่วน "องค์ความรู้ใหม่" ต้องมีโมเดลหรือแผนภาพเสมอ (ภาพที่ n) และใส่เพิ่มได้ในเนื้อหา (กรอบแนวคิด ขั้นตอนวิจัย)

1. เรียกสกิล `diagram-design` เลือกชนิดตามความหมาย: วงจร/ป้อนกลับ → loop, ขั้นตอน → process/flowchart, องค์ประกอบซ้อน → nested/layers, ทฤษฎี×หลักธรรม → quadrant/tree/matrix, การทับซ้อน → venn
2. ข้อความในภาพเป็นภาษาไทย ฟอนต์ `'TH Sarabun New','Sarabun','Leelawadee UI',Tahoma,sans-serif` สีเรียบ พิมพ์ขาวดำแล้วยังอ่านออก ไม่เกิน 9 กล่อง
3. Export PNG (≥ 2x) ไปที่ `figures/figN.png` เก็บ .html ต้นฉบับไว้ วารสารสาย มจร ขอภาพแยกเป็นไฟล์ (PDF/JPG/GIF/BMP) จึงทำ JPG อีกชุดตอนส่ง
4. ใต้ภาพมี "ที่มา: ผู้เขียน (ปี พ.ศ.)" หรือ "ที่มา: ประยุกต์จาก ..." และย่อหน้าอธิบายที่ไล่ทุกองค์ประกอบในภาพ

### ขั้น 8 — ปรับภาษาไม่ให้เป็น AI

ทำ 3 ชั้น ห้ามเปลี่ยนข้อเท็จจริง ตัวเลข การอ้างอิง ระดับความมั่นใจ และข้อความใน `[ตัวบท]`

เรียกสกิล `thai-humanizer` กับ draft (เส้นทางภาษาไทยสำหรับเนื้อหา เส้นทางภาษาอังกฤษสำหรับ Abstract) สกิลนั้นทำสามชั้นให้: นับร่องรอยด้วย `thai_style_check.py` → อ่านและแก้ตาม `thai-humanizer.md` → ผู้ตรวจสำนวนที่เห็นเฉพาะร่างภาษาไทย (ไม่ให้ refs.json บทคัดย่ออังกฤษ หรือ Abstract) ข้อที่ต้องย้ำกับบทความวารสาร:
- ข้อเสนอสำนวนทุกจุด รวมทั้งของผู้ตรวจ ต้องเทียบกับแหล่งก่อนรับ เพราะอาจทำความหมายแคบลงหรือเปลี่ยนสิ่งที่งานวัด
- ผู้ตรวจสำนวนชั้นนี้ต่างจากผู้ตรวจขั้น 9.5 ซึ่งเห็นทุกไฟล์และเน้นเนื้อหา

หลังปรับให้รัน `check_citations.py` และ `thai_style_check.py` ซ้ำ และเทียบทุกประโยคกฎหมายกับตัวบทอีกครั้ง

### ขั้น 9 — ตรวจก่อนส่ง

```bash
python -I <skill-dir>/scripts/check_citations.py <workdir>/draft.md --min 10
python -I <skill-dir>/scripts/check_claims.py <workdir>/draft.md <workdir>/refs.json --pages <เพดาน> [--ref-lists 2]
python -I <skill-dir>/scripts/check_terms.py <workdir>/draft.md <workdir>/terms.json
python -I <skill-dir>/scripts/check_reflist.py <workdir>/draft.md <workdir>/refs.json
python -I <thai-humanizer-dir>/scripts/thai_style_check.py <workdir>/draft.md
```

check_citations ต้องไม่มี ERROR; check_claims, check_terms และ check_reflist ทุก WARN ต้องแก้หรือบันทึกเหตุผล และไล่รายการ INFO (แหล่งที่ `cite_scope` จำกัด, มาตราที่อ้าง, คำย่อ) เทียบกับแหล่งด้วยตา; thai_style_check ไม่ควรเหลือ WARN ที่อธิบายไม่ได้ (บันทึกเหตุผลของ WARN ที่คงไว้ลง `checklist.md`) แล้วตรวจด้วยตนเองตามรายการ เขียนผลลง `checklist.md`:
- [ ] อ้างอิง ≥ 10 และทุกรายการอยู่ใน refs.json ที่ยืนยันแล้ว
- [ ] อ้างในเนื้อหาและท้ายเรื่องตรงกัน เรียงไทยก่อนอังกฤษ ตามตัวอักษร ผู้แต่งซ้ำใช้ `_____.`
- [ ] โครงสร้างหัวข้อครบและเรียงตามวารสาร
- [ ] บทคัดย่อ 300-400 คำ Abstract ตรงกับบทคัดย่อของบทความนี้ คำสำคัญ 3-5
- [ ] (วิจัย) วัตถุประสงค์ ↔ ผล ↔ อภิปราย ↔ สรุป ตอบกันครบทุกข้อ
- [ ] องค์ความรู้ใหม่มีภาพ + คำอธิบาย และเป็นสิ่งที่ผู้เขียนสังเคราะห์เอง ไม่ใช่สรุปซ้ำ
- [ ] (MCU) หลักธรรมเชื่อมกับเนื้อหาจริง เลขพระไตรปิฎกยืนยันแล้ว มีรายการ มหาจุฬาลงกรณราชวิทยาลัย. (2539) ท้ายเรื่อง
- [ ] ไม่มี `[รอข้อมูล` เหลือ ไม่มีข้อมูลวิจัยที่ผู้ใช้ไม่ได้ให้
- [ ] ความยาวตามเกณฑ์วารสาร
- [ ] ไล่ `references/review-lessons.md` ครบทุกหมวด (หลักฐานไม่เกินที่อ่าน, วิธีทบทวนทำซ้ำได้, สถิติ, นิยาม, กฎหมาย, โมเดล-ภาพ-ตารางตรงกัน, บรรณานุกรมรุ่นเดียวกับที่อ่าน)
- [ ] ผ่านด่านแรกของกองบรรณาธิการ: รูปแบบถูก ตรงขอบเขตวารสาร และแนะนำให้ผู้ใช้ตรวจความซ้ำ (CopyCat/อักขราวิสุทธิ์) ก่อนส่ง

### ขั้น 9.5 — จำลองการพิจารณาของผู้ทรงคุณวุฒิ (แนะนำ)

อ่าน `references/peer-review.md` แล้วใช้ **Claude Code subagent ผ่าน Agent tool เท่านั้น**: กองบรรณาธิการหนึ่งบทบาทจาก `../../agents/article-editor.md` และผู้ทรงคุณวุฒิสองถึงสามท่านจาก `../../agents/article-reviewer.md` แยกหนึ่งท่านต่อหนึ่ง subagent เลือกสาขาตามเนื้อหา บริบท โหมด MCU และระเบียบวิธีของบทความ

**ลำดับที่ตั้งใจให้จบใน 2 รอบ** (รอบเต็ม 1 + รอบยืนยัน 1) ไม่ใช่วนจนผ่าน:
1. **ด่านสคริปต์**: check_citations ERROR 0, check_claims WARN 0 (หรือบันทึกเหตุผลครบ), thai_style_check, และ check_linebreaks กับ PDF จริง + ดูภาพทุกหน้า ยังไม่เรียกใครจนกว่าจะผ่าน
2. **ด่าน editor คนเดียว** (โหมดด่านแรก): รูปแบบ ความยาว PDF ทีละหน้า ความครบของไฟล์ แก้จนผ่าน รอบนี้ถูกกว่ารอบผู้ทรงฯ มาก และปัญหารูปแบบที่ปล่อยไปจะปนในรายงานผู้ทรงฯ ทุกท่าน
3. **รอบเต็ม**: editor + ผู้ทรงฯ 2-3 ท่านขนานกัน → editor รวมผล → Claude หลักเทียบแหล่งทุกข้อ แก้ บันทึก สร้างไฟล์ใหม่ ตรวจด่าน 1 ซ้ำ
4. **รอบยืนยัน**: editor ดู PDF ใหม่ + ผู้ทรงฯ เฉพาะท่านที่ยังมีข้อค้าง ตรวจเฉพาะข้อค้าง ถ้าผ่านให้หยุด
5. ถ้ารอบยืนยันยังพบข้อบังคับใหม่ด้านสาระ ถือว่าร่างมีปัญหาที่ต้นทาง (โน้ตแหล่งไม่พอ งบความยาวผิด โครงไม่ตรงแม่แบบ) ให้กลับไปแก้ที่ขั้น 3/5/6 ของส่วนนั้นแล้วทำรอบเต็มใหม่ ไม่เปิดรอบ 3, 4, 5 เพื่อแก้ทีละข้อ

- ส่งชุดไฟล์จริงและแม่แบบคำสั่งรอบแรก/รอบถัดไปตามคู่มือ ตรวจจากร่างและแหล่งต้นทางพร้อมหลักฐานบรรทัด/หน้า หากยังไม่มี PDF ให้ทำขั้น 10 เพื่อสร้างฉบับตรวจ
- เรียกผู้ตรวจขนานตาม **บทความ × บทบาท** เขียนผลเฉพาะ `<workdir>/reviews/roundN/<role>.md` แล้วให้ editor รวมเป็น `<workdir>/review-roundN.md` เมื่อผลครบ บทความต่างกันต้องมี workdir แยกกัน
- Claude หลักเทียบข้อเสนอทุกข้อกับแหล่งก่อนรับ แก้ร่างและ `refs.json` ทำ `response-to-reviewers.md` แยกรอบ แล้วรัน `python -I <skill-dir>/scripts/check_response.py review-roundN.md response-to-reviewers.md --round N` ให้ครบทุกรหัสและสถานะอยู่ในชุดคำที่กำหนดก่อนเริ่มรอบถัดไป สร้างไฟล์ใหม่ก่อนตรวจซ้ำ แยกสถานะแก้ในร่างจากตรวจใน PDF แล้ว ข้อเสนอสำนวนของผู้ตรวจรับเฉพาะที่แก้ความหมาย/ขอบเขต/ประธานผิด ข้อเสนอรสนิยมไม่รับและตอบเป็นกลุ่ม การแก้ที่เพิ่มข้อความต้องมีจุดตัดคู่ในย่อหน้าเดียวกันหรือหน้าเดียวกัน

### ขั้น 10 — สร้างไฟล์ .docx

```bash
python -I <skill-dir>/scripts/build_docx.py <workdir>/draft.md <workdir>/<ชื่อ>.docx
```

ค่าเริ่มต้น (`--profile mcu`): A4 ขอบ 1 นิ้ว TH Sarabun PSK ประเภท 12 / ชื่อไทย 20 / ชื่ออังกฤษ 18 / ผู้เขียน 14 / หัวข้อ 18 / เนื้อหา 16 / ตาราง 14 pt ย่อหน้า 1.27 ซม. single spacing เนื้อหาจัดแบบ Thai Distributed (`--align justify|left`) อ้างอิงแบบ hanging indent ไม่ใส่เลขหน้า ฝังภาพจาก `figures/` พร้อมคำบรรยาย
โหมดทั่วไป: ปรับให้ตรงต้นแบบของวารสารด้วยตัวเลือก
- ขนาด/ฟอนต์: `--profile general --font ... --body-size --heading-size --title-size --title-en-size --title-en-upper yes|no --indent-cm --align justify|thai|left`
- ส่วนหัว: `--header-style left` (ชื่อเรื่องกึ่งกลาง ผู้เขียน/สังกัด/อีเมลชิดซ้าย) และ `--split-en-header` (ชื่อเรื่อง/ผู้เขียนอังกฤษขึ้นหน้าใหม่ก่อน Abstract)
- หน้า: `--page-numbers top-right|bottom-center`, `--page-break-before "บทนำ|References|..."`, `--center-headings "Abstract"`
- ภาพ/ตาราง: `--caption-align left`, `--table-style horizontal` (ไม่มีเส้นคอลัมน์)
- `--thai-wordbreak auto|on|off` แทรกตัวตัดคำไทยที่มองไม่เห็น (ต้องมี `pythainlp`) เพื่อให้ Word ตัดบรรทัดภาษาไทยถูกแม้เครื่องไม่มีตัวตัดคำไทย (ถ้าไม่มี บรรทัดจะขาดเฉพาะที่ช่องว่างและเกิดช่องโหว่ยาว) ถ้าเห็นคำถูกตัดกลางคำใน PDF (เช่น ตัวชี้ / วัด) ให้เพิ่มคำนั้นในไฟล์คำ บรรทัดละคำ แล้วส่ง `--thai-dict words.txt`
- `--keep-together "องฺ.อฏฺฐก. (ไทย)|…"` สตริงที่ห้ามตัดบรรทัดภายใน (คำย่อคัมภีร์ ชื่อเฉพาะที่มีจุด) ใช้แทนสคริปต์แก้ไฟล์หลังสร้าง
- ตาราง: `--fit-tables` ความกว้างคอลัมน์ตามปริมาณข้อความ (`--fit-min-cm 2.4` กันคำไทยในคอลัมน์แคบถูกตัดทีละตัว; ค่าเริ่มต้นคอลัมน์เท่ากัน) ช่วยลดบรรทัดเมื่อคอลัมน์หนึ่งเป็นป้ายสั้นอีกคอลัมน์เป็นหมายเหตุยาว
- ภาพ/ส่วนหัว: `--figure-width-in 5.6` (ย่อภาพเมื่อหน้าชนเพดาน; ตรวจขนาดอักษรในภาพด้วยสูตรใน `review-lessons.md` ฌ), `--author-size 16 --author-bold yes` และ `--received no` ให้ตรงแม่แบบวารสารที่ชื่อผู้เขียนใหญ่กว่าหรือไม่มีบรรทัด Received, `--source-align thai` ให้บรรทัด "ที่มา" ยาวใต้ตารางจัดเต็มบรรทัด
- **อย่าเขียนสคริปต์ python-docx แก้ไฟล์หลังสร้างต่อบทความ** ถ้าตัวเลือกยังไม่พอ ให้เพิ่มตัวเลือกใน `build_docx.py` แล้วทดสอบกับบทความเดิมว่าจำนวนหน้าไม่เปลี่ยน
ถ้าวารสารมี template .docx ของตนเอง ให้เทเนื้อหาลง template ด้วยสกิล `docx`

ตัวอย่าง (วารสารที่กำหนด TH Sarabun New 18/16, ผู้เขียนชิดซ้าย, เลขหน้าขวาบน, บทนำและอ้างอิงขึ้นหน้าใหม่):
```bash
python -I <skill-dir>/scripts/build_docx.py draft.md out.docx --profile general --font "TH Sarabun New" --title-size 18 --title-en-size 18 --title-en-upper no --heading-size 16 --align justify --header-style left --split-en-header --page-numbers top-right --page-break-before "บทนำ|References|เอกสารอ้างอิงภาษาไทย" --caption-align left --table-style horizontal
```
การจัดแนวหัวข้อ (เช่น Abstract) ให้ยึดข้อกำหนดเป็นลายลักษณ์อักษรของวารสาร ถ้าแม่แบบจัดต่างจากข้อกำหนด ให้ใช้ `--center-headings` เฉพาะเมื่อข้อกำหนดสั่งให้จัดกึ่งกลาง
วารสารที่ให้การอ้างอิงเป็นภาษาอังกฤษทั้งหมด: ใช้ชื่อภาษาอังกฤษของงานไทยจาก TCI/ThaiJO (`title_en`, `authors_en`, `journal_en` ใน refs.json) ใส่ `[in Thai]` และแนบรายการภาษาไทยแยกเป็นหัวข้อ `# เอกสารอ้างอิงภาษาไทย ...` ถ้าวารสารขอ

ตรวจหน้าตาและนับหน้า: แปลง .docx เป็น PDF (LibreOffice `soffice --headless --convert-to pdf` หรือ Microsoft Word ผ่าน COM บน Windows) แล้วเรนเดอร์หน้าเป็น PNG (เช่น `pypdfium2`) เพื่อดู ถ้าเครื่องไม่มีฟอนต์ที่วารสารกำหนด ตัวอักษรจะถูกแทนและจำนวนหน้าคลาดเคลื่อน ให้แนะนำผู้ใช้ติดตั้งฟอนต์ก่อนนับหน้าจริง ระหว่างนั้นประมาณด้วยฟอนต์ไทยที่มีในเครื่อง (เช่น Angsana New) และบอกว่าเป็นค่าประมาณ (ไฟล์ยังระบุฟอนต์ถูกต้อง) บน Windows ถ้าเรียก PowerShell ผ่านสคริปต์ไม่ได้ ให้เรียก Word COM เป็นคำสั่งบรรทัดเดียวในเครื่องมือ PowerShell โดยตรง บน Mac ใช้ Word for Mac ผ่าน AppleScript (`osascript`) ได้ (ใช้ TH SarabunPSK ที่มากับ Word แทนฟอนต์ที่ไม่มีในสำเนาที่แปลงได้) แต่ Word ถูก sandbox: ไฟล์ต้องอยู่ในโฟลเดอร์ที่ผู้ใช้ให้สิทธิ์แล้ว และถ้ามีหน้าต่าง "Grant File Access" ผู้ใช้ต้องกดเอง ไม่ควรใช้ LibreOffice นับหน้าเอกสารไทยถ้าไม่มีฟอนต์ที่กำหนด เพราะมันแทนด้วยฟอนต์อื่นและจำนวนหน้าคลาดได้เกือบเท่าตัว ก่อนเชื่อจำนวนหน้าจากเครื่องหรือวิธีใหม่ ให้แปลงฉบับเก่าที่รู้จำนวนหน้าแล้วเทียบก่อนทุกครั้ง

หลังสร้าง PDF **ทุกครั้ง** รันตัวตรวจคำตัดข้ามบรรทัดกับร่างรุ่นเดียวกัน ตรวจทั้งฉบับส่งและสำเนาที่ใช้ดูหน้า:

```bash
python -I <skill-dir>/scripts/check_linebreaks.py <workdir>/draft.md <workdir>/<ชื่อ>.pdf <workdir>/preview/<สำเนา>.pdf
```

ระบุเฉพาะ PDF ที่มีจริง รหัสออก 1 คือพบจุดต้องตรวจ; 2 คือตรวจไม่ครบหรือมีข้อผิดพลาด ให้เทียบจุดที่พบกับภาพหน้า PDF และร่าง รวมทั้งดูทุกหน้าด้วยตา ผลไม่พบไม่รับรองว่าไม่มีคำตัดผิด แก้เฉพาะจุดแล้วสร้าง PDF ใหม่ ตรวจซ้ำก่อนบันทึกว่า “แก้แล้ว-ตรวจใน PDF แล้ว” ในตารางตอบและ `checklist.md` (รายละเอียดข้อจำกัดใน `references/peer-review.md`)

สุดท้ายสรุปให้ผู้ใช้: ที่อยู่ไฟล์ จำนวนหน้าโดยประมาณ จำนวนอ้างอิง (ไทย/อังกฤษ) สิ่งที่ยังต้องเติมหรือตรวจเอง (ชื่อผู้เขียน อีเมล ความซ้ำ เลขพระไตรปิฎกที่ยังยืนยันไม่ได้) และขั้นตอนส่งผ่านระบบของวารสาร
